Parse the shell command into an AST before execution, so each sub-command and path argument is permission-checked separately.

## Why
- A single string pattern over the whole command is either too broad (`git *` approves `git status && rm -rf ~`) or useless (exact match never repeats).
- Chains, substitutions and redirects hide extra commands: opencode walks every `command` node, including ones nested in substitutions (`packages/opencode/src/tool/shell.ts:124`). Redirected statements were mis-parsed until `e7ff7143b6`.
- An "always allow" answer needs a human-meaningful scope (`git checkout *`, not `git *` or `git checkout main`); the prefix must come from command structure, not character counts (`ls*` matched `lsof` before `e7ff7143b6`).
- File-mutating commands (`rm`, `mv`, `cp`) can reach outside the project; their path arguments must be resolved and boundary-checked like file tools ([[workspace-boundary-check]]).

## Design space
- **Parser**: regex/tokenizer vs real grammar (tree-sitter bash + powershell wasm, opencode) vs no parsing (pi: no gate at all).
- **Unit of approval**: whole command vs each command node's source text (opencode).
- **"always" prefix**: first token vs arity dictionary keyed on longest prefix (opencode `BashArity`, 136 entries generated by an LLM prompt embedded in the file) vs user-authored.
- **Path checks**: none vs resolve args of a fixed file-command set and ask `external_directory` for out-of-project dirs, skipping args with variable expansion (opencode).
- **Skipped nodes**: directory-change builtins (`cd`, `pushd`, `popd`, `set-location`) produce no pattern (opencode).
- **Coverage gaps**: commands run outside the shell tool (opencode command templates' `` !`cmd` `` expansion, [[side-door-input-bypasses-hooks]]).

## Implementations
- [[opencode--shell-command-permission-parsing|opencode]] — legacy `ShellTool` parses with web-tree-sitter, adds each command node's source as a `bash` pattern and `BashArity.prefix(tokens) + " *"` as its "always" pattern; file-command path args trigger `external_directory` first.
