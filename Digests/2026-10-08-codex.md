## 3 most surprising findings

1. **The system prompt is model data, not harness code, and the repo copies are fossils.**
   - Since `a1abd53b6a` (2026-02-09, "Remove offline fallback for models") the base prompt comes only from the model catalog (`models.json`, bundled or fetched remotely).
   - The five `codex-rs/core/gpt*_prompt.md` files are referenced nowhere, yet sweeping commits still edit them. Orphaned templates (`codex-rs/core/templates/agents/orchestrator.md`, `codex-rs/core/templates/collab/experimental_prompt.md`) are also still being edited.
   - Since `c9253c4977` (2026-10-05) the Responses `instructions` field is not sent at all; the base prompt travels as a developer message.
   - Prompt engineering is measured and still reverted. "you MUST use apply_patch as a standalone tool" took bypasses from ~22% to 0% (`f6a152848a`, 2025-09-30). It was reverted the next day (`5d78c1edd3`), then replaced by a permissive rule with carve-outs (`0ad1b0782b`).
   - → [[per-model-system-prompt]] · [[prompt-ownership]] · [[edits-bypass-patch-tool]] · [[no-offline-per-model-prompts]] · [[no-top-level-instructions-field]] · [[message-role-layering]]

2. **Stateless on purpose, cached anyway.**
   - Every request resends the full input with `store: false` and replays encrypted reasoning (`codex-rs/core/src/client.rs:961,996-1012`; decision `591cb6149a` "Always send entire request context").
   - Latency and cost are recovered in other ways:
     - `prompt_cache_key` set to the session id;
     - Responses-over-WebSocket with incremental append (`d75626ad99`);
     - opaque **server-side** compaction via `/responses/compact` (`838531d3e4`, on by default `cac0a6a29d`).
   - Context changes are also cache-aware. Environment, permissions and mode are typed "world state" sections, re-sent only when their snapshot changes. A mid-conversation sampling-setting change keeps the request parameter pinned.
   - → [[cache-strategy]] · [[no-server-stored-conversation]] · [[compaction-locus]] · [[world-state-diff-injection]] · [[cache-preserving-config-update]]

3. **Safety is the opposite pole from pi, and its failure log reads like a security course.**
   - The protection is layered:
     - a kernel sandbox per OS (Seatbelt / bubblewrap + seccomp / Windows restricted tokens), with network off;
     - approval policies, and execpolicy prefix rules;
     - "guardian", an LLM reviewer that sees authorship-labelled evidence and the root user's real messages;
     - a loopback egress proxy with domain lists;
     - a patched shell that routes every `execve` to the harness;
     - self-hardening of the harness process.
   - The history shows each layer being bypassed:
     - the agent wrote its own escalation surface (`.git/hooks`, `.codex/`, `.agents/`, `.aws/`), patched one path at a time from `80555d4ff2` (2025-08-01) to `1d804e91b7` (2026-09-25);
     - side-channel syscalls;
     - symlinked roots;
     - escalation dropping deny-read rules;
     - model-proposed approval rules that were too broad.
   - pi calls the same machinery "security theater".
   - → [[isolation-strategy]] · [[os-level-sandbox]] · [[llm-approval-reviewer]] · [[delegated-authorization-provenance]] · [[per-exec-interception]] · [[agent-writes-its-own-escalation-config]] · [[protected-workspace-metadata]] · [[no-sandbox]]

## 1 thing to build
**[[world-state-diff-injection]] + [[model-requested-context-reset]].**
- Keep the model-visible environment (cwd, permissions, mode, date, AGENTS.md) as typed sections with comparison snapshots. Emit only the sections that changed, so the cached prefix survives.
- Give the model `get_context_remaining` / `new_context_window` plus a low-budget reminder, so *it* chooses when to reset instead of being compacted mid-thought.
- Both are cheap to build on any harness that already has [[xml-prompt-boundaries]].

## 1 question to argue
**Should a harness own its system prompt and tool surface, or should the model vendor?**
- codex moves both into the model catalog: per-model prompt, tool list, truncation policy and context window, with tools named in the model's own training dialect.
- pi keeps a ~680-token harness-owned prompt and four generic tools, and pays for it in [[foreign-harness-tool-hallucination]].
- Vendor ownership gives the best results on its own models. Harness ownership gives portability and auditability, since the repo shows what the model actually sees.
- Which failures in [[Prompting Failures]] would each choice have prevented? → [[prompt-ownership]] · [[dedicated-vs-shell-tools]] · [[provider-breadth]]

## Method

- Mechanical checks:
  - all 961 cited codex hashes resolve;
  - every codex `path:line` is inside its file;
  - no broken links and no duplicate aliases;
  - 1039 of 1053 miner-cited hashes were carried into the vault; the remaining timeline items went into [[codex]].
