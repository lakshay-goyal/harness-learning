## 3 most surprising findings

1. **Many limits are enforced only by prompt text, and the code has drifted away from the prompts.**
   - **Max steps.** On the last step the legacy loop appends an *assistant* message, "Tools are disabled until next user input" (`packages/core/src/session/runner/max-steps.ts:3`). It still sends the full tool set: `tools` is passed and `toolChoice` is unset (`packages/opencode/src/session/prompt.ts:1278-1286`). The default cap is `Infinity` (`prompt.ts:1178`). Only v2 sets `toolChoice: "none"` (`packages/core/src/session/runner/llm.ts:222`).
   - **Plan mode.** It "Disallows all edit tools" (`packages/opencode/src/agent/agent.ts:158`), yet `bash` is never denied. The reminder escalated to "ZERO exceptions" (`packages/opencode/src/session/prompt/plan.txt:9`). A plan-mode bypass through subagents went through three fixes in five weeks, ending with plan simply denied `task: general` (`agent.ts:165-166`).
   - **Edit tool.** `edit.txt`/`write.txt` still promise a read-before-edit check, but the check was deleted (`76a141090e`).
   - **Borrowed prompts.** Prompts copied from other harnesses reference things opencode doesn't have, including a developer's Claude Code plans path.
   → [[step-budget-limit]] · [[plan-mode]] · [[read-only-mode-bypass-via-subagent]] · [[read-only-mode-bypassed-via-shell]] · [[step-limit-enforced-only-by-prompt]] · [[tool-description-drifts-from-implementation]] · [[borrowed-prompt-foreign-references]] · [[no-read-before-write-guard]]

2. **A second runtime is being built spec-first, around prompt-cache stability.**
   - The v2 runtime (`packages/core` + `packages/llm`, from `76ee87ead8` 2026-06-03) replaces "the system prompt" with typed **Context Sources**. An immutable **Context Epoch** baseline is held for the cache. Changes arrive as chronological **Mid-Conversation System Messages** at a safe provider-turn boundary (`CONTEXT.md:7-37`).
   - Only `claude-opus-4-8` gets a native mid-conversation `role:"system"` (`packages/llm/src/protocols/anthropic-messages.ts:356`). Every other model gets escaped `<system-update>` user text.
   - The specs have already drifted from the code. Session move no longer clears the epoch (`d8bf79225f`). Spill-write failure is reported as a failure, not as lossy success. The build ruleset starts with `*:*:allow`, although the spec says "ask by default".
   - v2 still lacks the doom-loop check and session retry that legacy has (TODO `packages/core/src/session/runner/llm.ts:55`).
   → [[transcript-carried-system-prompt]] · [[cache-stable-prompt-prefix]] · [[event-sourced-session-store]] · [[spec-driven-agentic-development]] · [[prompt-cache-strategy]]

3. **The provider boundary absorbs most of the pain, and its fixes get reverted.**
   - `packages/opencode/src/provider/transform.ts` and `packages/opencode/src/provider/provider.ts` have 291 fix commits between them, more than twice the main loop file (`packages/opencode/src/session/prompt.ts`, 123).
   - Replay-shape fixes are the most revert-prone class: reasoning pairing `8c2aec43b8`→`3c3d6b65c2`, empty blocks `d8a15e7bc9`→`d69366b00c`, signed-thinking reorder `42173bca4b`→`a763a14d44`.
   - Session retry was **unbounded** until `c78986831c` (2026-08-11). The stream idle timeout flipped 2 min → 5 min → off → 5 min.
   - Many constants are byte-identical to pi's: 2000 lines / 50 KB, 2000 px images, JPEG ladder 80/85/70/55/40, OAuth port 1455. That suggests shared lineage (unverified).
   → [[transcript-replay-repair]] · [[signed-reasoning-replay]] · [[auto-retry-backoff]] · [[tool-schema-lowering]] · [[Constants]]

## 1 thing to build
**A prompt-claim linter for modes and limits.**
- For every mode or limit (plan, max-steps, read-only subagent, `.env` protection), declare one machine-checkable contract: which tools are present, which permission rules apply, and what `toolChoice` is.
- Generate the reminder text *from* that contract.
- Add a test that fails when a prompt sentence names a tool, agent, check or error string that the request does not actually contain.
- opencode's v2 `toolChoice: "none"` and `origin/v2`'s "guidance only for tools actually present" base prompt are halfway there.

→ [[ephemeral-reminder-injection]] · [[dynamic-tool-guidelines]] · [[prompt-names-unavailable-tools]] · [[permission-ruleset]]

## 1 question to argue
**Are permission prompts security, or theater with better UX?**
- pi has none ("Security theater", [[no-permission-prompts]]).
- opencode has a full allow/ask/deny ruleset with tree-sitter bash parsing and `external_directory` asks. But its build agent defaults to `*: allow` (`packages/opencode/src/agent/agent.ts:115-135`), `.env` reads can go through `bash` or `grep` ([[secret-guard-bypassed-by-other-tools]]), plan mode leaks through bash, and v2 hides rejection feedback from the model.
- If the default is allow and the boundary is only lexical ([[workspace-boundary-check]]), what does the ask flow buy beyond a pause button?

→ [[permission-prompts-vs-none]] · [[shell-command-permission-parsing]] · [[no-sandbox]]

## Also notable

- **Doom loop.** 3 identical tool calls trigger a `doom_loop` permission ask, not an abort (`d983b9485d`). → [[repeated-tool-call-detection]] · [[identical-tool-call-loop]]

- **Unknown context size.** Custom models default to context 0, which silently disables auto-compaction. Tool-output pruning has been off by default since 2026-04. → [[auto-compaction]] · [[tool-output-pruning]]

## Method
1. **Mining.** 6 parallel miners covered legacy organs, v2 core/llm, prompt archaeology, fix commits, constants, and features/absences. 4 of them were resumed once to close gaps (llm protocols, codemode, SDK patches, ACP/share/control-plane), without spawning new agents.
2. **Registry.** I built a closed registry from ~70 proposed slugs, which collapsed to 29 new concepts. For example, 3 miners each invented a repeated-call concept; those became one. ~94 new failure slugs were folded into 79.
3. **Writing.** 5 writers each owned disjoint group folders, with Constants, Absences and Tradeoffs handled by a separate writer. Findings were pre-split into per-group bundles.
4. **Verification.**
   - Mechanical: all 639 opencode hashes resolve, 0 path:line refs point past EOF, wikilinks resolve, and 13 duplicate aliases were removed. A coverage audit found 332/344 finding blocks already represented; the rest were closed by the verifiers.
   - Semantic: 2 verifiers re-read ~2100 cites and fixed ~50 errors: ~32 wrong line ranges or files (8 of them introduced by a verifier script and then fixed), 6 overstated claims, and 3 wrong hash attributions. 9 "unverified" claims were confirmed.
   - Every cross-group handoff was resolved.
5. **Still unverified:**
   - the pi/opencode constant lineage
   - why batch, the read-before-write guard and pruning were removed or switched off
   - the runtime exploitability of the v1 symlink escape and of the GitHub-run permission hang
   - whether legacy "always" approvals can override a configured deny.
